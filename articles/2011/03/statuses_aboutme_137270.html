ただ、核となるアイデア自体は、ポイントを送りはじめてからずっと温めてきたものなので、いきなりペンション組んだりもできてる。動くかどうかやってみたのは初でも、長い蓄積があったとは言える。当初はもっと複雑なことも考えてた気もするけど、いい具合に忘却過程がはさまれて、シンプルにしか初められないようにされた…という感じかな。

JRF 2011年3月3日

$ID_CONDENSER のところ、f(x + y) > f(x) + f(y) かつ f(x) -> 1 (x -> inf) というのを探したが、見つからなかったので、f(x) = x ** (1 + r) という関数にした。

これを f(x) -> 1 にしようと例えば f(x) = x ** (1 + r * exp(-x/N)) とか f(x) = x ** (1 + r / (x ** (1.0/N))) とかも考えた。


JRF 2011年3月3日

しかし、gnuplotで 2 * f(x) と f(2 * x) を描くと、どうしても 2 * f(x) > f(2 * x) なる部分が見つかり、条件 f(x + y) > f(x) + f(y) に合わない。

逆に大きい部分では ID を分けるのをむしろうながしたほうがいいかもしれず、そうすると、f(x) = x ** (1 + r / (x ** (1.0/N))) も良さそうな感じなのだが、わかりやすさを優先した。

JRF 2011年3月3日

むしろ、他の者もこのプログラムを使うようになると、基礎ポイントの多い者に、ペンション登録を促し、$PENSION_FEE を払うことを選択させたほうがいいのではないかという読みもある。そう促す方法というのは、また考えないといけないが。


JRF 2011年3月3日

修正 「f(x) -> 1」→「f(x) - x -> 0」。

書くとき 1 + r 乗が 1 に近づくというのと混同してしまった。つまり、x をとても大きくしていくと、y = f(x) が y = x の直線に近づくということ。

複雑な関数に結局しないのは、「わかりやすさを優先」のほか、私一人で基礎ポイントを付けている限り、そんな多額にはならないので問題ないというのもある。
